# `config!`

> The `tokitai::config!` runtime-override macro: change a tool's
> description, tags, or per-parameter hints **after** the binary has
> been compiled, without recompiling the `#[tool]` impl block.

## Syntax

```rust,ignore
tokitai::config! {
    TypeName {
        tool_name: {
            desc: "…",
            tags: ["…", "…"],
            params: {
                param_name: {
                    desc: "…",
                    example: "…"
                }
            }
        }
    }
}
```

`config!` is **not** an attribute — it is a `#[proc_macro]`
function-like macro. It is invoked at the call site (typically
`main.rs`), at runtime or at static-init time, and the overrides are
pushed into the `tokitai_core::GLOBAL_CONFIG_REGISTRY`. The
`__get_tool_definitions` function (generated by every `#[tool]`,
`#[wrap]`, or `#[openapi]` impl block) reads from the registry on its
first call and applies the overrides to the matching `ToolDefinition`.

## Arguments

| Key | Type | Required? | Description |
|---|---|---|---|
| `TypeName` | `Ident` | yes | The type the `#[tool]` impl block was applied to. |
| `tool_name` | `Ident` | yes | The tool name (matches the `name` attribute or, by default, the method name). |
| `desc` | `&str` | no | Override the tool description. |
| `tags` | `[&str]` | no | Override the tool tags. |
| `params` | block | no | A nested block of per-parameter overrides. |
| `params.param_name.desc` | `&str` | no | Override the parameter description. |
| `params.param_name.example` | literal | no | Override the parameter example value. |
| `params.param_name.default` | literal | no | Override the parameter default value. |

## Examples

### Minimal

```rust,ignore
use tokitai::config;

config! {
    Calculator {
        add: {
            desc: "Add two integers."
        }
    }
}
```

### Common usage

```rust,ignore
use tokitai::config;

config! {
    WeatherService {
        get_weather: {
            desc: "Fetch current weather for a city",
            tags: ["weather", "read-only"],
            params: {
                city: {
                    desc: "City name, e.g. 'Tokyo' or 'Berlin'",
                    example: "Tokyo"
                },
                unit: {
                    desc: "Temperature unit",
                    example: "celsius"
                }
            }
        }
    }
}
```

### Edge case

The macro accepts multiple `TypeName { ... }` blocks in a single
invocation, and within one block multiple `tool_name: { ... }` blocks.
Order does not matter; later blocks with the same `TypeName` /
`tool_name` / `param_name` keys **win** (last write wins).

```rust,ignore
use tokitai::config;

config! {
    Calculator {
        add: { desc: "English description" }
    }

    WeatherService {
        get_weather: {
            desc: "Fetch weather",
            params: { city: { desc: "City name" } }
        }
        get_forecast: {
            desc: "Fetch forecast",
            params: { city: { desc: "City name" } }
        }
    }
}
```

If `config!` is called **after** `tool_definitions()` has already been
called once, the override is queued but the existing `LazyLock` is not
invalidated. To force a re-read, call `MyType::configure_tool(name, &[])`
to re-initialise the cached definitions.

## Generated code

`config!` is invoked at runtime, so its output is a series of
`ToolConfig` values pushed into the global registry:

```rust,ignore
// What config! expands to (semantically):
let _ = ::tokitai_core::GLOBAL_CONFIG_REGISTRY.configure(
    "WeatherService::get_weather",
    &[
        ::tokitai_core::ToolConfig::Desc("Fetch current weather for a city"),
        ::tokitai_core::ToolConfig::Tags(vec!["weather", "read-only"]),
        ::tokitai_core::ToolConfig::ParamDesc("city", "City name, e.g. 'Tokyo' or 'Berlin'"),
        ::tokitai_core::ToolConfig::ParamExample("city", serde_json::json!("Tokyo")),
        ::tokitai_core::ToolConfig::ParamDesc("unit", "Temperature unit"),
        ::tokitai_core::ToolConfig::ParamExample("unit", serde_json::json!("celsius")),
    ],
);
```

The actual implementation lives in
[`tokitai-macros/src/tool/config/registry.rs`](../../tokitai-macros/src/tool/config/registry.rs)
and pushes entries into a `tokitai_core::GLOBAL_CONFIG_REGISTRY`
typed as `BTreeMap<String, Vec<ToolConfig>>`. The registry is consulted
inside `__get_tool_definitions`:

```rust,ignore
fn __get_tool_definitions() -> &'static [::tokitai_core::ToolDefinition] {
    static TOOLS: ::std::sync::LazyLock<::std::vec::Vec<::tokitai_core::ToolDefinition>> =
        ::std::sync::LazyLock::new(|| {
            let mut defs = ::std::vec::Vec::from([/* original definitions */]);
            for def in &mut defs {
                let configs = ::tokitai_core::GLOBAL_CONFIG_REGISTRY.get(&def.name);
                if !configs.is_empty() {
                    def.apply_configs(&configs);
                }
            }
            defs
        });
    &TOOLS
}
```

Source: [`tokitai-macros/src/tool/mod.rs`](../../tokitai-macros/src/tool/mod.rs)
(`pub fn config` and the `__get_tool_definitions` block).

## Interactions

- **With `#[tool]`**: every `#[tool]` impl block generates a
  `configure_tool(name, &[])` method that flushes a single entry. The
  `__get_tool_definitions` function applies the registry entries
  every time it is cold-initialised.
- **With `#[openapi]`**: `#[openapi]` deliberately emits a no-op
  `configure_tool` (see
  [`openapi.md`](openapi.md)) because OpenAPI-derived metadata is
  fixed at compile time. `config!` is silently ignored for `#[openapi]`
  methods.
- **Priority order** (from `tokitai-macros/src/lib.rs` doc-comment):
  1. `#[tool(desc = "...")]` > doc comments (compile-time).
  2. `tokitai::config!` > `#[tool]` attributes (runtime).
  3. `param_tool` per-parameter > default inference (compile-time).
- **Process-global state**: the registry is a `static` in
  `tokitai_core`. Calling `config!` from multiple crates in the same
  binary is safe; entries are merged by `(type_name, tool_name)` key.

## Errors

`config!` is permissive: unknown keys are silently ignored, and
type-checking happens at runtime against the registry rather than at
expansion time. The macro does not currently emit any
`compile_error!` or `compile_warning!`.

If a `config!` invocation refers to a `TypeName` that has no
`#[tool]` impl block in the same binary, the entry sits in the
registry forever and is never applied. There is no dead-config warning
in v0.5.0.
